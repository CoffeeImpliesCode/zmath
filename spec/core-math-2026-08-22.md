# CORE-MATH scalar corpus contract

This document defines schema version 5 of the typed scalar and non-scalar corpus.
The contract applies only to `zmath-testing`.
The runtime must not link external CORE-MATH, MPFR, Arb, GMP, or FLINT libraries.

## Pinned inputs

Schema version 5 pins these inputs:

| Item | Required value |
| --- | --- |
| CORE-MATH repository | `https://gitlab.inria.fr/core-math/core-math.git` |
| CORE-MATH revision | `3bafed75e3c22399531857d63a3fa0e24bfb42fa` |
| MPFR precision | 512 bits |
| Arb precision | 512 bits |
| Rounding policy | `nearest_even` |

The CORE-MATH revision is an immutable 40-digit lowercase commit identifier.
A branch, tag, abbreviated commit, or moving reference is invalid.
The pin identifies the upstream source baseline.
It does not state that `zmath` implements an upstream function.

The `mpfr_arb` evaluator keeps MPFR and Arb computation at exactly 512 bits.
MPFR produces a candidate with `MPFR_RNDN`.
Conversion to the target format also uses round-to-nearest, ties-to-even.
Arb evaluates the same finite mathematical result at 512-bit precision.
The Arb enclosure must round to one target bit pattern.
The candidate and proof must agree on that pattern.
The `exact_bits` evaluator does not use MPFR or Arb for its bit-preserving paths.
The `algebraic` evaluator uses exact GMP rationals for finite dyadics and 512-bit Arb/MPFR enclosures for algebraic roots.
The producer must fail if an evaluator cannot decide, if a proof crosses a rounding boundary, or if results differ.
It must not increase precision silently or write a best-effort record.

## Exact oracle and boundary protocol

All target-format boundary arithmetic uses exact dyadic or integer relations.
The MPFR/Arb oracle uses fixed 1,024-bit boundary containers where their capacity is sufficient for exact binary boundary values.
This fixed boundary capacity does not change the 512-bit numerical evaluation precision.
The protocol does not adapt precision after an ambiguity.

Fixed MPFR512 evaluation followed by target RNE can double-round
`atan2((2^52-1)*2^-1074, 2)`.
The generator may correct the initial candidate by one adjacent lower-magnitude value only when every condition below holds:

1. Exact dyadic arithmetic proves `t = abs(y/x)` equals the midpoint above the corrected candidate.
2. The proof establishes `0 < t < 1`.
3. Arb512 proves `t^3` is less than the gap from `t` to the next lower rounding midpoint.
4. The analytic bound `t - t^3 < atan(t) < t` places the exact result inside the corrected candidate's rounding cell.

The correction preserves the result sign.
Any unresolved equality, enclosure, or boundary condition fails closed.

For exponentials and powers, Arb512 can prove positive overflow in the log domain.
This proof does not construct the enormous result.
For negative noninteger `lgamma` inputs, the Arb proof uses reflection and evaluates `lgamma` at a positive argument.

## Formats

Schema version 5 accepts only these exact format identifiers:

| Identifier | IEEE 754 format | Width | Hexadecimal digits |
| --- | --- | ---: | ---: |
| `h` | binary16 | 16 bits | 4 |
| `f` | binary32 | 32 bits | 8 |
| `d` | binary64 | 64 bits | 16 |

The identifier `q` is outside this contract.
Schema version 5 must reject `q`.
Schema version 5 must reject `bfloat16`.
It must also reject aliases, uppercase identifiers, and all unknown identifiers.

## Target C23 scalar family

This section defines the target `zmath` scalar names. It does not grant implementation or manifest acceptance.

### Independent status terms

The contract keeps these facts separate:

- **Target** means that a root generic and its suffixed scalar names are required by this API.
- **Implemented** means that the current source exports the suffixed symbol.
- **Manifest-accepted** means that an operation-format row has status `correct` or `bounded`.
- **Corpus-evidenced** means that immutable rows for one accepted pair passed the stated oracle checks.
- **Whole-domain-proved** means that exhaustive evidence or a separate proof covers every input in that operation-format domain.

A target symbol is not necessarily implemented.
An implemented symbol is not necessarily manifest-accepted.
Corpus evidence covers only its stored inputs unless a separate whole-domain proof applies.

Schema version 5 has 347 sorted typed manifest rows.
The authoritative C operation table maps each manifest operation-format key exactly once.
It assigns 150 descriptors to `exact_bits`, 126 to `mpfr_arb`, 49 to `algebraic`, and 22 to `definitional`.
All 347 descriptors are manifest-accepted as `correct` with `max_ulp = 0`.
Full publication and replay verified 72,035,642 records on the scalar lane and on the scalar-backed vector lane.
The scalar benchmark receipt covers all 347 descriptors and retains only repetition zero for each descriptor.
It is a timing record, not acceptance or a domain proof.
The publication contains 62 exhaustive unary binary16 campaigns.
Selected campaigns do not prove whole-domain correctness.

### Implemented-source snapshot

The current source exports the `zmath.ieee` and `zmath.scalar` families described in this contract, their shared result types, and the corresponding generic root operations. `src/c23_public_surface_test.zig` validates those module and root signatures for `f16`, `f32`, and `f64`.

The source also exports the six C23 root narrowing operations (`fadd`, `fsub`, `fmul`, `fdiv`, `ffma`, and `fsqrt`) and the Annex H format-pair forms from `zmath.scalar`.

These exports do not imply manifest acceptance.

### Generic dispatch

The public root generic is `zmath.<op>`. Its floating argument type selects one exact suffixed scalar symbol:

| Floating type | Suffix |
| --- | --- |
| `f16` | `h` |
| `f32` | `f` |
| `f64` | `d` |

For a normal operation, all floating arguments have the same type. Dispatch does not widen, narrow, or coerce them.
The scalar symbol is the operation name followed by the suffix. Thus, `exp{h,f,d}` means `exph`, `expf`, and `expd`.

The existing `sinh`, `sinf`, and `sind` symbols are the sine family.
The target hyperbolic symbols are `sinhh`, `sinhf`, and `sinhd`.
The existing `cosh`, `cosf`, and `cosd` symbols are the cosine family.
The target hyperbolic cosine symbols are `coshh`, `coshf`, and `coshd`.
The target tangent symbols are `tanh`, `tanf`, and `tand`.
The target hyperbolic tangent symbols are `tanhh`, `tanhf`, and `tanhd`.

`zmath.abs` is the C23 `fabs` operation. Its scalar names remain `absh`, `absf`, and `absd`.
The target has no `fabs`, `fabsh`, `fabsf`, or `fabsd` aliases.

The target has no `q`, `f128`, bfloat16, decimal, or long-double family.
Generic dispatch rejects those types.

### Pure-value and rounding profile

The scalar and IEEE APIs use a pure-value profile.
A call communicates only through its return value, including an explicit result struct when required.
No result contract uses `errno`, floating-point exception flags, or hidden mutable status.
`zmath` does not read or write `errno`.
It does not inspect, clear, report, or restore floating-point exception flags.
Incidental processor flags are outside this contract.

Callers must keep IEEE round-to-nearest, ties-to-even active for each scalar call.
`zmath` does not read, validate, set, or restore the process rounding mode.
Behavior under another active rounding mode is unsupported.
An operation-defined direction argument, such as the `fromfp` direction, does not change the process environment.
Narrowing operations compute the exact mathematical operation and round once to the declared destination type.

### Basic and rounding family

Each operation below has one root generic and the `h`, `f`, and `d` scalar names:

```text
abs ceil floor nearbyint rint round roundeven trunc
lrint llrint lround llround
fromfp ufromfp fromfpx ufromfpx
```

The `lrint`, `llrint`, `lround`, and `llround` families return this shared result type:

```zig
pub const IntegerResult = struct { value: i64, ok: bool };
```

A valid conversion returns `.{ .value = result, .ok = true }`.
A NaN, either infinity, or a rounded value outside the `i64` range returns `.{ .value = 0, .ok = false }`.
Invalid input does not trap and does not use a numeric sentinel.

The `fromfp`, `ufromfp`, `fromfpx`, and `ufromfpx` families return an integral value in the input floating type `T`.
Each family has the target signature `(value: T, round: FromFpRound, width: u32) T`.
The `u32` width maps the C `unsigned int` argument.

```zig
pub const FromFpRound = enum {
    nearest_even,
    nearest_from_zero,
    toward_zero,
    toward_positive,
    toward_negative,
};
```

### Exponential and logarithmic family

```text
exp exp2 exp10 expm1 exp2m1 exp10m1
log log2 log10 log1p logp1 log2p1 log10p1
```

`log1p` and `logp1` are separate public spellings for the same mathematical operation.

### Trigonometric, inverse, and pi-scaled family

```text
sin cos tan asin acos atan atan2
sinpi cospi tanpi asinpi acospi atanpi atan2pi
```

`atan2` and `atan2pi` return `Atan2Result(T) { value: T, resolved: bool }`.
The root generics and all suffix variants use this result shape.
The public symbols are wrappers, and direct CORE-MATH kernel symbols remain private.
The wrappers own all NaN, axis, zero, and infinity results.
The `value` field is an operation result only when `resolved=true`.
Every ordinary result and every documented special result sets `resolved=true`.
This includes a quiet NaN selected from a NaN input.
If a finite kernel cannot prove one nearest-even result, the call sets `resolved=false`.
The `value` field is then the format's positive canonical quiet NaN.
This false status reports an unresolved computation, not a mathematical NaN or a domain error.
No valid input may trap or terminate the process.
The wrappers do not guess a result bit when a kernel cannot decide.
They do not call host libm or use `fenv` or `errno`.

### Hyperbolic and inverse hyperbolic family

```text
sinh cosh tanh asinh acosh atanh
```

The suffix rule applies to every name in this list. Hyperbolic H names use the operation-plus-suffix spelling, such as `sinhh`.
The H symbols are `sinhh`, `coshh`, `tanhh`, `asinhh`, `acoshh`, and `atanhh`.

### Power, root, and norm family

```text
pow pown powr compoundn sqrt cbrt rsqrt rootn hypot
```

`compoundn`, `pown`, and `rootn` use the C23 `long long int` exponent or degree.
The zmath mapping is `i64`.
They return `PowerResult(T) { value: T, ok: bool }`.
The root generics and all suffix variants use this result shape.
The accepted integer range is `-64` through `+64`, inclusive.
When `n` is below `-64` or above `+64`, the range check precedes all input-value rules.
The `value` field is then the format's positive canonical quiet NaN, and `ok=false`.
Every call with `-64 <= n` and `n <= 64` sets `ok=true`.
The `value` field then holds the specified result, including an in-range domain or NaN result.
Thus, `ok` reports only whether `n` is in the accepted range.

`compoundn(x, n)` computes `(1 + x)^n`.
The pinned CORE-MATH `compound` source takes a floating exponent in its direct implementation.
It is not direct evidence for the C23 `compoundn` contract.
The power families use the ordered IEC 60559 and glibc value precedence below.
An earlier rule wins.
For the three `PowerResult` families, each result below describes `value` when `ok=true`.
This project adopts the return values, but it does not adopt `fenv` or `errno` effects.

For `pow`, signaling-NaN quieting precedes an identity that would otherwise hide that signaling NaN.
Quiet NaNs do not override `pow(x, +/-0)=+1` or `pow(+1, y)=+1`.
`pow(-1, +/-infinity)` is `+1`.
After these identities, the first remaining NaN in `(x, y)` parameter order wins.
For an infinite exponent, `abs(x)` relative to one selects `+0` or `+infinity`.
For a zero or infinite base and a finite nonzero exponent, the exponent sign selects zero or infinity.
Such a result is negative only when the base is negative and the exponent is an odd integer.
A finite negative base with a finite noninteger exponent returns the positive canonical quiet NaN.

For `pown`, a signaling NaN is quieted before the `n=0` identity.
Then `n=0` returns `+1`, including for a quiet NaN base.
A remaining NaN is quieted.
Zero and infinity results use the exponent sign, and a negative sign occurs only for an odd `n`.

For `powr`, four domain cases precede ordinary NaN selection.
They are a negative non-NaN base, `0^0`, `1^infinity`, and `infinity^0`.
Each domain case returns the positive canonical quiet NaN.
After these cases, the first NaN in `(x, y)` parameter order wins.

For `compoundn`, a signaling NaN is quieted first.
A non-NaN `x < -1` then returns the positive canonical quiet NaN.
Next, `n=0` returns `+1`, including for a quiet NaN.
A remaining NaN is quieted.
For `x=-1`, a positive `n` returns `+0`, and a negative `n` returns `+infinity`.
For `x=+infinity`, a positive `n` returns `+infinity`, and a negative `n` returns `+0`.

For `rootn`, `n=0` returns the positive canonical quiet NaN before NaN selection.
A remaining NaN is quieted.
A negative nonzero value with an even `n` returns the positive canonical quiet NaN.
Zero and infinity results preserve a negative sign only for odd `n`.
The sign of `n` selects the zero or infinity magnitude.

Each finite direct result from a power, root, or pi-scaled family must be correctly rounded in `nearest_even`.
For a result-container function, this rule applies to a finite `float` only when its status field is true.
For `pown`, `compoundn`, and `rootn`, the rule applies only when `-64 <= n` and `n <= 64`.
A false status supplies no mathematical result and makes no accuracy claim for its sentinel `float`.
This requirement does not claim that a current implementation satisfies it.
A composition of separately rounded operations is not final evidence.
This includes post-scaling by an approximation of `1/pi`, reciprocal-exponent power, and target-format power-by-squaring.

The bounded power kernels use fixed, format-specific integer storage.
They use 32 `u64` limbs for `f16`, 256 limbs for `f32`, and 2,048 limbs for `f64`.
`pown` and `compoundn` keep finite dyadic arithmetic exact and round once.
`rootn` uses exact candidate and midpoint comparisons instead of a rounded reciprocal-power composition.
These storage bounds prevent allocation. They do not specify a universal execution-time bound.

### Error and gamma family

```text
erf erfc lgamma tgamma
```

`lgamma` returns `LgammaResult(T) { value: T, sign: i2 }`.
The root generic and all suffix variants use this result shape.
For a finite non-pole input, `value` is the rounded value of `log(abs(Gamma(x)))`.
The `sign` field is the sign of `Gamma(x)` and is either `-1` or `+1`.
No public result uses `sign=0`.

At each finite negative-integer pole and at either zero, `value` is `+infinity`.
The `sign` field is `-1` at each finite negative-integer pole and at `-0`.
It is `+1` at `+0`, either infinity, and every NaN.
For either infinity, `value` is `+infinity`.
For a NaN, `value` follows the common same-width NaN policy.

`lgamma` follows the pure-value and caller-RNE profile.
It returns only `value` and `sign` and exposes no `errno` or floating-point exception status.
It does not inspect, clear, report, set, or restore floating-point exception flags.
Incidental processor flags remain outside this contract.
The API has no global `signgam` value and no hidden mutable gamma-sign state.

### Remainder, decomposition, and scaling family

```text
fmod remainder remquo
frexp modf ilogb llogb logb ldexp scalbn scalbln
```

`frexp` returns `FrexpResult(T) { fraction: T, exponent: i32 }`.
`modf` returns `ModfResult(T) { fractional: T, integral: T }`.
`remquo` returns `RemquoResult(T) { value: T, quotient: i32 }`.
These structs replace C output pointers, and each field keeps its C23 meaning.
`remquo` uses the nearest integer quotient, with ties to even.
Let `n` be that quotient.
Its quotient field is `sign(x/y) * (abs(n) mod 8)`.
Thus, the contract exposes exactly three low quotient bits.
A selected NaN, an infinite dividend, or a zero divisor sets `quotient=0`.
The NaN result follows the common NaN policy.
An infinite dividend or zero divisor without a NaN returns the positive canonical quiet NaN.
A zero dividend with a nonzero divisor, or a finite dividend with an infinite divisor, returns the dividend and `quotient=0`.

`frexp` returns `exponent=0` for zero, infinity, and NaN.
Its fraction preserves a zero or infinity bit pattern.
For a NaN, its fraction preserves the sign and payload and sets the quiet bit.

`modf` returns the input zero in both fields.
For a finite value with magnitude below one, the integral field is a zero with the input sign.
For an integral finite value, the fractional field is a zero with the input sign.
For infinity, the fractional field is a zero with the input sign, and the integral field is the input infinity.
For a NaN, both fields contain the same sign-preserving, payload-preserving quiet NaN.

`ilogb` returns `minInt(i32)` for either zero and `maxInt(i32)` for infinity or NaN.
`llogb` uses the corresponding `i64` limits.
`logb` returns `-infinity` for either zero, `+infinity` for either infinity, and a quieted input NaN for NaN.

The `ldexp`, `scalbn`, and `scalbln` families preserve a NaN sign and payload.
A quiet NaN is bit-identical.
A signaling NaN sets only the format quiet bit.
These rules freeze the current deterministic remquo and decomposition outputs.
They are not delegated to host library behavior.

### Fused, difference, maximum, and minimum family

```text
fma fdim fmax fmin
fmaximum fminimum
fmaximum_mag fminimum_mag
fmaximum_num fminimum_num
fmaximum_mag_num fminimum_mag_num
```

The legacy `fmax` and `fmin` families use a deterministic local policy.
This policy is a zmath contract, not a portable C guarantee.
With exactly one NaN operand, they return the numeric operand.
With two NaN operands, they return the first operand after preserving its sign and payload and setting its quiet bit.
For an opposite signed-zero tie, `fmax` returns `+0` and `fmin` returns `-0`.

The `fmaximum` and `fminimum` families use the IEC 60559 maximum and minimum relations.
The magnitude and number variants apply their C23 relation after selecting the operation family.

The binary16 `fmah` kernel multiplies and adds exact integer dyadics.
It performs one final round-to-nearest, ties-to-even packing step.
It does not use a widened host FMA followed by a second target-format rounding.

### Narrowing family

C23 7.12.14 defines these binary-format functions:

```zig
pub fn fadd(x: f64, y: f64) f32;
pub fn fsub(x: f64, y: f64) f32;
pub fn fmul(x: f64, y: f64) f32;
pub fn fdiv(x: f64, y: f64) f32;
pub fn ffma(x: f64, y: f64, z: f64) f32;
pub fn fsqrt(x: f64) f32;
```

The target also includes the C23 Annex H `_FloatM` forms for the supported public formats:

```text
f16addf32  f16subf32  f16mulf32  f16divf32  f16fmaf32  f16sqrtf32
f16addf64  f16subf64  f16mulf64  f16divf64  f16fmaf64  f16sqrtf64
f32addf64  f32subf64  f32mulf64  f32divf64  f32fmaf64  f32sqrtf64
```

For example, `f16addf32(f32, f32) f16`, `f32fmaf64(f64, f64, f64) f32`, and `f16sqrtf64(f64) f16`.
Each narrowing operation computes as if to infinite precision and rounds once to the declared destination type.
The implementation must form the exact intermediate in portable software and round only at the destination.
Target-dependent extended precision, contraction, or a direct narrowing shortcut is not final correctness evidence.

For every cross-width narrowing operation, the first NaN in parameter order selects the result.
The result preserves its sign and the high-order diagnostic payload bits that fit the destination.
It discards lower payload bits and then sets the destination quiet bit.
These names encode the destination before the source. They are not same-type generic operations.

These format-pair declarations are Annex H forms. They are not Annex F declarations.

The target omits all `_FloatNx`, `q`, `f128`, bfloat16, decimal, and long-double forms.

### C23 operations owned by `zmath.ieee`

The scalar module does not duplicate representation and successor operations.
The target `zmath.ieee` module owns these C23 equivalents:

```text
canonicalize{h,f,d}
copySign{h,f,d}
nan{h,f,d}
nextAfter{h,f,d}
nextToward{h,f,d}
nextUp{h,f,d}
nextDown{h,f,d}
```

For input type `T`, `canonicalize{h,f,d}(value: T)` returns `CanonicalizeResult(T) { value: T, ok: bool }`.
This value-returning local adaptation replaces the C output pointer and integer success result.
Each supported `h`, `f`, or `d` input returns `ok=true`.
A non-NaN `value` is bit-identical to the input, including zero and infinity.
A quiet NaN is bit-identical to the input.
A signaling NaN preserves its sign and diagnostic payload and sets only the format quiet bit.
The supported fixed formats never return `ok=false`.
No supported fixed-format call can produce a failure result, so no fixed-format failure value exists.
That status is reserved for a future representation which the API cannot canonicalize.

The `nan` family has the target signature `nan{h,f,d}(tag: []const u8) T`.
The tag grammar is one or more ASCII hexadecimal digits: `[0-9A-Fa-f]+`.
The parser accepts no sign, `0x` prefix, separator, whitespace, empty tag, or non-ASCII byte.
It interprets the tag as an unsigned diagnostic-payload integer.
The value must fit 9 bits for `h`, 22 bits for `f`, or 51 bits for `d`.
A valid tag produces a positive quiet NaN with that diagnostic payload.
An invalid, empty, or out-of-range tag produces the positive canonical quiet NaN.

The `nextToward` family has the target signature `nextToward{h,f,d}(value: T, toward: f64) T`.
Its comparator is `f64` because `f64` is the widest public format.

C leaves this cross-format NaN mapping implementation-defined.
When `toward` is an `f64` NaN, `nextTowardh` and `nextTowardf` preserve its sign.
They retain the high-order diagnostic payload bits that fit the target, discard lower bits, and set the target quiet bit.
For `f64` to `f16`, source payload bits 50 through 42 become destination payload bits 8 through 0.
For `f64` to `f32`, source payload bits 50 through 29 become destination payload bits 21 through 0.
This mapping is a zmath contract, not a portable C guarantee.

Classification predicates, signaling tests, ordered comparisons, and bit conversion also remain in `zmath.ieee`.

### Optional IEC 60559 extension family

C23 Annex F makes these operations optional extensions outside baseline 7.12:

```text
totalOrder totalOrderMag getPayload setPayload setPayloadSig
```

The target suffix families are `totalOrder{h,f,d}`, `totalOrderMag{h,f,d}`, `getPayload{h,f,d}`, `setPayload{h,f,d}`, and `setPayloadSig{h,f,d}`.
Each has one root generic with the same operation name.

`setPayload` and `setPayloadSig` return `PayloadResult(T) { value: T, ok: bool }`.
This struct replaces the C result pointer with a value and success flag.
These optional operations remain a by-value API fixed to the `h`, `f`, and `d` formats.
They do not expose C output pointers or a dynamic format parameter.

C leaves the accepted NaN payload range implementation-defined.
This project accepts a fixed-format floating argument only when it represents an allowed numeric integer payload.
For `setPayload`, both signed zeros represent `q=0`.
The exact success ranges and result bits are:

| Format | Accepted `q` | `setPayload` result bits | Accepted `s` | `setPayloadSig` result bits |
| --- | --- | --- | --- | --- |
| `h` | `0` through `511` | `0x7e00 OR q` | `1` through `511` | `0x7c00 OR s` |
| `f` | `0` through `4,194,303` | `0x7fc00000 OR q` | `1` through `4,194,303` | `0x7f800000 OR s` |
| `d` | `0` through `2,251,799,813,685,247` | `0x7ff8000000000000 OR q` | `1` through `2,251,799,813,685,247` | `0x7ff0000000000000 OR s` |

Each successful `setPayload` call returns the exact positive quiet NaN in the table with `ok=true`.
Each successful `setPayloadSig` call returns the exact positive signaling NaN in the table with `ok=true`.
Zero, including `-0`, is invalid for `setPayloadSig` because it would encode infinity.
A negative nonzero, fractional, subnormal, infinite, NaN, or out-of-range argument is invalid for either setter.
Each failure returns the exact `PayloadResult(T) { value=+0, ok=false }`.
This policy is a zmath contract, not a portable C guarantee.
These optional operations remain a by-value API fixed to the `h`, `f`, and `d` formats.
They do not expose C output pointers or a dynamic format parameter.

### Special-value policy

The oracle and implementation must use exact target-format bit patterns.
The format encodings are:

| Format | `+0` | `-0` | `+1` | `+infinity` | `-infinity` | Canonical quiet NaN |
| --- | --- | --- | --- | --- | --- | --- |
| `h` | `0000` | `8000` | `3c00` | `7c00` | `fc00` | `7e00` |
| `f` | `00000000` | `80000000` | `3f800000` | `7f800000` | `ff800000` | `7fc00000` |
| `d` | `0000000000000000` | `8000000000000000` | `3ff0000000000000` | `7ff0000000000000` | `fff0000000000000` | `7ff8000000000000` |

When an operation returns a same-width input NaN, it preserves the sign and diagnostic payload.
It then sets the format quiet bit.
The quiet-bit masks are `0200`, `00400000`, and `0008000000000000` for `h`, `f`, and `d`.
A quiet NaN remains unchanged.
A signaling NaN becomes a quiet NaN.

When an operation returns a narrower NaN, let `S` and `D` be the source and destination diagnostic-payload widths.
The destination payload is `source_payload >> (S - D)`.
The operation preserves the sign and then sets the destination quiet bit.

Unless an operation has a stricter rule, the first NaN argument in parameter order selects the result.
An invalid non-NaN input returns the positive canonical quiet NaN for its format.
An operation-specific documented rule takes precedence.
This includes the local `fmax` and `fmin` policy and the C23 number-preferring variants.

`exp`, `log`, and `sin` use the exact special tables in this document.
The maximum, minimum, magnitude, and number families use their specified local, C23, or IEC 60559 NaN and signed-zero relations.
The producer writes exact constants directly and does not ask a host library to choose special-value bits.

Signed-zero and infinity results follow each operation's documented policy.
That policy can be local, C23, or IEC 60559.


## Manifest schema

`zmath-testing/test/corpus/manifest.toml` is the machine-readable manifest.
A schema version 5 parser must require these root keys with the exact values in the manifest:

- `schema_version`
- `core_math_repository`
- `core_math_revision`
- `mpfr_precision_bits`
- `arb_precision_bits`
- `rounding`
- `formats`
- `reserved_formats`
- `rejected_formats`
- `operation_spelling`
- `columns`
- `hexadecimal`
- `uncertainty_policy`
- `special_policy`

The root `special_policy` must equal `"zmath_c23_v1"`.
Every function row's `special_policy` token must equal the root token.

`operation_spelling = "c23_hfd_lowercase_v1"` is the only valid operation-spelling declaration.
The parser must reject a missing key, an unknown key, or a duplicate key.
It must reject duplicate function rows and unsorted function rows.
Each `[[function]]` row has exactly these nine keys, once and in this order:

```text
op, provenance, status, arity, inputs, result, oracle, special_policy, max_ulp
```

`op` is the exact case-sensitive ASCII operation name assigned by the authoritative C table.
For a standard H/F/D family, the typed descriptors select the format and `operation_spelling` derives the public scalar symbol by appending lowercase `h`, `f`, or `d`.
Dedicated encoded operations, including the names in the Narrowing family, remain exact and are not transformed.
The provenance vocabulary is exactly `["zmath", "core_math"]`.
Each function row must use one nonempty ordered subset for `provenance`.

The `<format>` in a structure descriptor is the format of each floating field.
`struct:integer:<format>` retains the floating input format for row ordering; its integer field is always `i64`.
A structure descriptor records a corpus record layout.
Most rows mirror a public return shape; `struct:complex` mirrors the concrete `Complexf` and `Complexd` fields because no generic `Complex(T)` is public, and `struct:luSolve` is an adapter layout with no public type, because `lu` returns `?LuMat2f` through `?LuMat4d` and `solveLu` returns `?Vec2f` through `?Vec4d`.
A refused factorization or solve publishes `+0`, `+0`, and `false`, because a `null` has no record encoding.
No descriptor grants implementation, corpus evidence, or manifest acceptance.

`status` is one of `unsupported`, `correct`, and `bounded`.
`max_ulp` is canonical unsigned decimal text.
Unsupported and correct rows require `max_ulp = 0`.
Bounded rows permit any declared non-negative `max_ulp` value, including zero.
An `unsupported` row requires `oracle = "none"`.
A `correct` or `bounded` row requires a non-`none` oracle.
The parser records these declarations and does not infer capability from status.

Schema 5 accepts these oracle values:

- `none` for an unsupported row.
- `exact_bits` for direct IEEE bit and integer evaluation.
- `algebraic` for exact dyadic/rational evaluation and certified algebraic-root evaluation.
- `mpfr_arb` for the fixed-precision transcendental evaluator and its certified reductions.
- `definitional` for direct checks of IEEE representations or published algebraic conventions.

A `definitional` row checks the published representation or convention without an MPFR/Arb enclosure.
It does not establish whole-domain numerical accuracy.
The class has its own evaluator entry point.
A different evaluator category cannot satisfy a `definitional` descriptor.

Schema 5 retains two typed forms introduced by schema 4:

- The `round_mode` input form carries one of the four IEEE 754 rounding directions:
  `nearest_even`, `toward_zero`, `toward_positive`, or `toward_negative`. It is a
  distinct form from `fromfp_round`, because the two vocabularies number their
  directions differently and a value of one must never be reinterpretable as a
  value of the other. The direction is an input value, never a descriptor, so an
  operation that takes a direction contributes exactly one manifest row.
- The `classification` result form carries one of the six IEEE 754 classes: `zero`,
  `subnormal`, `normal`, `infinity`, `quiet_nan`, or `signaling_nan`. It is a real
  enumeration, not an integer, because an integer result would misstate the type.

The authoritative C operation table assigns exactly one evaluator class to each of the 347 descriptor keys.
The generator requires the row's oracle evidence to match that assignment.
The descriptor digest deliberately excludes status and oracle snapshots.
It covers the profile, numerical descriptors, provenance, special policy, ULP bound, and authoritative C signature.
This permits candidate evidence review before a manifest promotion.

A row can change from `unsupported` to `correct` or `bounded` only after implementation, corpus evidence, and a manifest update.
Within schema version 5, that row transition may update `status`, `oracle`, and `max_ulp` together.
The resulting row must satisfy the relation rules above.
A `correct` row uses `max_ulp = 0`.
A `bounded` row uses an approved non-negative `max_ulp`.
These value changes use existing fields and do not require a `schema_version` bump.
A schema change requires a `schema_version` bump, including a change to fields, allowed values, field order, or validation semantics.

The correct-rounding requirement for finite power, root, and pi-scaled results is a target requirement.
It is not an implementation-status or manifest-acceptance claim without the matching evidence.

## `exp`, `log`, and `sin` API

Each `exp`, `log`, and `sin` function has one scalar argument and uses a lower-case H/F/D suffix:

```zig
pub fn exph(x: f16) f16;
pub fn expf(x: f32) f32;
pub fn expd(x: f64) f64;
pub fn logh(x: f16) f16;
pub fn logf(x: f32) f32;
pub fn logd(x: f64) f64;
pub fn sinh(x: f16) f16;
pub fn sinf(x: f32) f32;
pub fn sind(x: f64) f64;
```

These signatures do not take a `RoundMode` argument. Callers must keep IEEE round-to-nearest, ties-to-even active for each call. `zmath` does not read, validate, set, or restore the process floating-point environment (`fenv`). Behavior under other rounding modes is unsupported.

The initial `sinh`, `sinf`, and `sind` symbols are the sine family.
They are not the hyperbolic family. The target hyperbolic H/F/D names are `sinhh`, `sinhf`, and `sinhd`.

Each record stores the operation, ordered provenance, arity, typed arguments, result descriptor, typed result fields, and `max_ulp`.

## Exact rounding policy

For a finite mathematical result, round once to the target format.
Use round-to-nearest with ties to an even least-significant significand bit.
Use gradual underflow.
Do not flush subnormal values to zero.
Overflow follows IEEE 754 round-to-nearest behavior.
A nonzero result that rounds to zero keeps the sign of the exact result.
Callers must keep IEEE round-to-nearest, ties-to-even active when they call these `zmath` functions.
`zmath` does not read, validate, set, or restore the process floating-point environment (`fenv`).
Behavior under other rounding modes is unsupported.

The `exact_bits` evaluator compares direct IEEE and integer model bits.
The `algebraic` evaluator uses exact GMP rational arithmetic for finite dyadic operations and certified MPFR/Arb enclosures for irrational algebraic roots.
The `mpfr_arb` evaluator uses the fixed 512-bit MPFR candidate and 512-bit Arb proof described above.
The atan2 midpoint correction and log-domain overflow proof are part of that certified protocol.

For a `correct` row, replay requires an exact match for every typed result field and output class.
For a `bounded` row, replay requires an exact match for special values and a ULP distance no greater than `max_ulp` for finite normal or subnormal values.
The ULP distance applies only when both finite results have the same sign.
A sign difference fails.
Replay uses stored typed outputs; it does not invoke an oracle or substitute a host result.

The finite-result requirement applies to every accepted operation.
Power, root, and pi-scaled operations additionally require their declared correctly-rounded proof and matching evaluator evidence.

## Special values

These encodings are exact:

| Format | `+0` | `-0` | `+1` | `+infinity` | `-infinity` | Canonical quiet NaN |
| --- | --- | --- | --- | --- | --- | --- |
| `h` | `0000` | `8000` | `3c00` | `7c00` | `fc00` | `7e00` |
| `f` | `00000000` | `80000000` | `3f800000` | `7f800000` | `ff800000` | `7fc00000` |
| `d` | `0000000000000000` | `8000000000000000` | `3ff0000000000000` | `7ff0000000000000` | `fff0000000000000` | `7ff8000000000000` |

For a same-width NaN input, preserve its sign and diagnostic payload.
Set the quiet bit.
The quiet-bit masks are `0200`, `00400000`, and `0008000000000000` for H, F, and D.
A quiet NaN remains unchanged.
A signaling NaN becomes a quiet NaN.

For a narrower result, preserve the source NaN sign and map the high-order source diagnostic payload bits that fit the destination.
Discard lower source payload bits, then set the destination quiet bit.

An invalid non-NaN input produces the positive canonical quiet NaN for its format.
No corpus output may encode a signaling NaN.
The `qnan` class requires an exact match of the sign, quiet bit, and payload.

The operation rules are:

| Operation | Exact special-value behavior |
| --- | --- |
| `exp` | `exp(+0)` and `exp(-0)` are `+1`. `exp(+infinity)` is `+infinity`. `exp(-infinity)` is `+0`. |
| `log` | `log(+0)` and `log(-0)` are `-infinity`. `log(+1)` is `+0`. `log(+infinity)` is `+infinity`. A negative non-NaN input produces the canonical quiet NaN. |
| `sin` | `sin(+0)` is `+0`. `sin(-0)` is `-0`. Either infinity produces the canonical quiet NaN. |

The NaN-input rule takes precedence over each operation rule unless that operation has an explicitly stricter rule.
The producer encodes exact constants directly and does not ask a host library to choose their bits.

## Fail-closed rules

The producer must not publish `COMPLETE` after any uncertainty.
A failed run can leave partial records with an `.incomplete` marker.
Unapproved profiles and invalid filters must fail before output setup.
Uncertainty includes an evaluator disagreement, an Arb interval that spans two target results, an unresolved midpoint correction, an unknown special-value policy, a descriptor mismatch, or a missing source sentinel.
It must not increase precision silently or write a best-effort record.

Replay must reject metadata, profile, descriptor, scope, record-order, count, or artifact-digest mismatches.
It must not skip a bad row, substitute a host result, invoke an external oracle, or accept a nearby value.
The scalar benchmark must reject the same publication-integrity failures before measurement.

Schema version 5 defines 347 typed descriptors and five oracle values.
The selected campaign matrix covers all descriptor keys. The checked-in manifest status is the acceptance authority. The final unfiltered publication, its replay, and its scalar benchmark receipt are recorded.
Corpus evidence applies only to stored tuples unless an exhaustive campaign or separate proof covers the whole operation-format domain.

The pure-value profile applies to corpus production and consumption.
The corpus does not record `errno` or floating-point exception flags.
No producer may use host libm, fenv, or errno to choose an output bit pattern.
