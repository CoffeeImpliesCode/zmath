# zmath

Zig 0.16.0 IEEE and scalar math for `f16`, `f32`, and `f64`, plus a portable `@Vector` layer over the elementwise scalar operations, including the result-struct, integer-argument, integer-returning, boolean-returning, and narrowing forms. The repository uses `jj` with colocated Git.

## Layout

- `src/root.zig` is the root module and exports `zmath.ieee`, `zmath.scalar`, `zmath.vector`, `zmath.complex`, `zmath.quaternion`, `zmath.matrix`, `zmath.linalg`, `zmath.geometry`, and `zmath.algebra`. `src/ieee.zig` and `src/scalar.zig` implement the current IEEE and scalar APIs. `src/vector.zig` holds the float-to-float `@Vector` surface and re-exports `src/vector_core.zig` (shared per-lane helpers), `src/vector_struct.zig`, `src/vector_intarg.zig`, `src/vector_narrow.zig`, and `src/vector_ieee.zig` for the other lane-to-non-lane forms. It also re-exports the six `Vec*` value types from `src/vector_value.zig`, which is a different layer that shares the module path.
- Source and tests are flat under `src/`: scalar kernels use `src/scalar*.zig`, the vector layer uses `src/vector*.zig`, C kernels use `src/coremath_*.[ch]`, and tests use `src/*_test.zig`.
- The non-scalar modules are `src/complex.zig`, `src/quaternion.zig`, `src/matrix.zig`, `src/linalg.zig`, `src/geometry.zig`, and `src/algebra.zig`. `src/matrix.zig` holds the one sanctioned public structural generic, `Mat`; every other public type is concretely named. `src/geometry.zig` carries the `PredicatePolicy` enum and its `adaptive_exact` path evaluates predicates in exact integer arithmetic on a fixed `[132]u64` limb array.
- The vector layer uses Zig's portable `@Vector` and is lowered by the compiler per target; it has no hand-written per-ISA kernels and no runtime dispatch.
- There is no `src/scalar/`, `src/simd/`, or `src/tests/` directory.
- `build.zig` exposes the `zmath` module, installs a demonstration executable, and defines `run`, `test`, and `docs` steps.
- The sibling [`zmath-testing`](../zmath-testing/) project owns oracle generation, corpus replay, and benchmarks.

## Numerical contracts

- Handle IEEE-754 NaNs, signed zero, infinities, and subnormals according to [API.md](API.md) and the [scalar contract](spec/core-math-2026-08-22.md).
- Use the [schema-5 corpus manifest](../zmath-testing/test/corpus/manifest.toml) for acceptance status. An export or a sampled corpus does not prove whole-domain accuracy.
- Every `@Vector` lane runs the identical accepted scalar kernel, so a vector result is bit-for-bit the scalar result for that lane; never re-derive a polynomial for the vector path. Zig forbids a struct as a `@Vector` element type, so the thirteen result-struct operations and `pown`, `compoundn`, and `rootn` return a lane-ordered `[N]Result` array instead of a `@Vector`. That is a language limitation, not a placeholder, and the array shape buys no throughput over a scalar loop.
- `build.zig` requires `+fma` on x86/x86_64; other architectures are checked for IEEE binary32/binary64 storage, a supported byte order, and `_BitInt(128)` or native `__int128`. Binary16 C entry points use a `uint16_t` bit ABI, so native C `_Float16` is optional. C and Zig share `src/scalar_fma_target.zig`'s compile-time FMA policy; targets without native binary32 or binary64 fusion use the bounded integer dyadic engine. The vector layer adds no dispatch or hand-written SIMD, and there is no baseline SSE2 fallback.
- Do not allocate dynamically in evaluation loops. Keep scratch storage statically bounded or caller-supplied.
- `armeb-linux` in `Debug` is expected to report 950 of the 956 tests. The six failures are the pre-existing `toVector` and `fromVector` lane-order tests, which read the returned `@Vector` register: LLVM's ARM big-endian backend computes the returned vector's big-endian reversal into a scratch register it never reads, returns the unreversed register, and the caller then applies one extra reversal, so each forwarded result arrives with one lane swapped. Reading the published bytes is correct, which is why the published-lane test passes there, and no source form of `toVector` avoids the defect. This is a pre-existing upstream compiler defect, not a project regression, because the same six tests fail at the parent commit. Keep those tests in the suite: never drop the failing tests or the target to make a run green, and record the count instead.
- Sweep boolean masks through the project build, with operands filled at run time under `std.mem.doNotOptimizeAway` and one width per compiled program. The measured facts are that the repository test binary passes at every swept width on the executed big-endian targets, while standalone programs of a different shape report width 16 wrong on 7 of 16 marked lanes on `loongarch64-linux` in `Debug` and every power-of-two width wrong for both ordering kernels on `aarch64_be-linux` in `Debug`; both of those probes omit the project's C kernels and the `-ffreestanding -fno-math-errno -ffp-contract=off` cflags. Constant folding is not what differs: re-running the width 16 probe with operands built from a runtime loop index reproduced the failure, and that same width is clean under `ReleaseSafe` in the same program. A width that fails in one program shape and passes in another is an unresolved report about program-shape sensitivity rather than proof of a width-specific defect, so record it as open instead of excluding the width or asserting it.

## Commands

Run at the repository root:

- `zig build` installs the demonstration executable at `zig-out/bin/zmath` and makes the `zmath` module available to consumers. It does not install a compiled library artifact.
- `zig build run` runs the demonstration. `zig build test` runs the local unit tests. `zig build docs` generates documentation from the demonstration executable.
- `cross-test` uses `cross-test.profile.sh` to attempt the complete version-pinned Tier 1/2 matrix. Append `-- -Doptimize=ReleaseSafe` for optimized correctness checks; `cross-test --list` shows detected runners. Missing OS runtimes remain `build_only`, never a test pass; `--require-runners` fails incomplete coverage and can be used with a runnable `--targets` subset. `--jobs N` sets the concurrency of both the build and the run phase, `--build-jobs N` the concurrency inside one build, so a wide matrix pays off through `--jobs`. Cross-target unit results are not corpus acceptance or profiling. The executed `cross-test` results for the big-endian lane-publication work are a `Debug` run over all 53 Tier 1/2 targets, `19` pass, `1` fail, `33` build_only, the one failure being `armeb-linux` in `Debug` at `950` of `956`, and a `ReleaseSafe` run over `armeb-linux` and `aarch64_be-linux`, `2` pass, `0` fail, both reading "All 956 tests passed." That `ReleaseSafe` run is the first receipt for the integer publication route, which needs an `aarch64_be` target and a non-`Debug` mode at once. Native `Debug` and native `ReleaseSafe` are both `956` of `956`.
- `zig build test-build` installs `bin/zmath-test` without running it, for the profile's artifact hook. The `cross-test` host command and its sibling helpers must already be installed. It does not replace the gate.
- `zig fmt --check .` checks formatting. `gate` runs the full gate: format, build, test, AST check, and the configured linters `ziglint`, `zlint`, `zbc` and `zwanzig`. `gate` is provided by the development environment rather than by this repository, so run it as `direnv exec . gate`. The gate is not green on this tree: it also fails on frozen lint debt that predates the lane-publication work, `ziglint` 265, `zlint` 269, `zbc` 145 and `zwanzig` 375 findings over the same 213 files, so never report it as green. The gate measured on the current tree is fmt, build, test and ast-check OK, `ziglint` 263, `zlint` 263, `zbc` 146 and `zwanzig` 353 in 8 rule classes, `cross-test` 19 pass, 1 fail and 33 build_only on the known `armeb-linux` `Debug` case, and exit 1; the quoted baseline is the campaign's frozen measured source snapshot, not the parent commit, so the two sets are not a parent-commit comparison. Per file, `zbc` moved `src/vector_core.zig` 13 to 6, `src/geometry.zig` 28 to 22 and `src/vector_test.zig` 2 to 0 against `src/vector_value_test.zig` 2 to 8, `src/linalg.zig` 19 to 23, `src/vector_value.zig` 24 to 28 and `src/geometry_test.zig` 0 to 2, so the byte-staging change removed seven findings and the net rise of one belongs to the wider uncommitted change set rather than to the lane-publication files, and `src/vector_value.zig` is byte-equivalent to the parent commit.
- `jj st` shows working-copy status. Use `jj`, not raw Git commands.

Run oracle and benchmark commands in sibling `zmath-testing`, not here. Its accepted corpus profile is `x86_64-linux-gnu.2.38`, CPU `haswell`, and `ReleaseSafe`. See [API.md: Tests and benchmarks](API.md#tests-and-benchmarks) for its current build steps.

Development dependencies and tools are declared in `devenv.nix`. Do not install system or
development libraries imperatively. Use direnv or `devenv shell`; run `direnv allow` after
changing the environment.
